Technical notes

All three kernels run as WebAssembly in the live view. Browser float32 uses the browser’s floating-point implementation; Saturn’s compiled float path uses software helpers. The separate Saturn section only displays recorded physical-console measurements.

Every path receives the same quantized vertices and matrix coefficients. Inputs and matrices are converted once for float outside timing. Float error measures transform rounding and excludes the common matrix/trigonometry quantization. Safe and prepared fixed-point outputs are checked bit for bit on every displayed pose.

The safe batch is the previous optimization: one matrix bound check, three direct products per row, one floor and one clamp. The prepared path scans the immutable mesh once and caches its coordinate bounds. Each new matrix then proves that products, sums and outputs fit, allowing the hot loop to use a defined branchless floor and omit clamps. Both paths retain the full-range fallback. The code panels show equivalent single-row arithmetic; source links contain the complete kernels.

The prepared time includes matrix qualification once per batch. Capture also measures qualification and kernel time independently for diagnosis. Mesh scanning is part of one-time input preparation, alongside float conversion. Mutating the input mesh requires preparation again. Matrix construction, rendering and precision checks are outside timing for every path.

Live timings update every 500 ms using a rolling median of five adaptive samples, each spanning at least 0.75 ms. Capture pauses the loop, warms all paths and takes 21 samples, increasing repetitions until each spans at least 5 ms. First, second and third measurement positions rotate. Times include the JS-to-WASM call. Capture holds the result for export; Play resumes live sampling. Browser timing resolution, JIT, power state and other tabs affect results. Export includes sample durations and counts, all three distributions, component timings, precision checks and the WASM hash.

Reduced-motion preferences start the scene paused. Scene or detail changes clear old timings. The shared JavaScript projection supplies the visual comparison; timings measure transforms, not FPS.
