# Variable-length decoding of byte symbols (experimental, contract tag `vlc-1`)

[`vlc_experimental.h`](include/sh2zam/vlc_experimental.h) decodes prefix-coded byte symbols
from a bit stream on the SH-2: a bounded marker-bit reader, a length-limited canonical code
builder and a two-level table decoder, with a hand-written SH-2 kernel and a portable C path
that give the same bytes and reader state. It is the entropy-decoding core of a tile codec. It
came from a contributing Claude session's Saturn port work and was reviewed and hardened for
this library; every test uses synthetic alphabets generated by the tests.

**Evidence tiers: HOST and MODELLED only.** No emulator or console run of these kernels has
been done. Cycle numbers come from the Yabause SH-2 interpreter with flat RAM (no cache, no
wait states); they are not Saturn timings.

## API

| Function | What it does |
| --- | --- |
| `sh2z_vlc_reader_init(r, stream, units)` | Start reading `units` 16-bit units (2 × units bytes). |
| `sh2z_vlc_reader_ok(r)` | False once any bit past the end of the stream has been consumed. |
| `sh2z_vlc8_build(t, freq, w, lmax, len_out, code_out)` | Code lengths (exact rule below), canonical codes and the table, from frequencies. |
| `sh2z_vlc8_build_lengths(t, len, w, lmax, code_out)` | The table from code lengths, for example lengths read from a stream. |
| `sh2z_vlc8_check(t)` | Is a loaded table safe to decode with? |
| `sh2z_vlc8_decode(t, r, dst, n)` | Decode `n` symbols; the SH-2 kernel on SH-2. Returns `sh2z_vlc_reader_ok(r)`. |
| `sh2z_vlc8_decode_portable(t, r, dst, n)` | The C path, same contract and results. |

The header is the contract. In short:

- **Stream.** 16-bit units, low byte first, bits consumed least significant first; a code is
  written first bit first (the canonical code bit-reversed, as in DEFLATE). The decoder reads
  only the stream's `2 × units` bytes. Bits past the end read as zero.
- **Malformed and truncated input.** For any stream contents and any `n`, a decode reads only
  the table, the reader and the stream, writes exactly `dst[0..n)` and the reader, and takes
  O(n) time. A decode that consumes a bit past the end returns false, and so does every later
  decode on that reader. All `n` bytes are written either way, each a symbol of the table.
  With a complete code every bit string decodes, so truncation is the only stream error.
- **Tables.** `w` (1..8) bits index the first level; longer codes go to a pool of `u16`
  groups of up to 2^7 entries. A built table always passes `sh2z_vlc8_check`; a table loaded
  from untrusted data must pass it before decoding. The format holds codes up to `w + 7` bits,
  so never a 16-bit code: `sh2z_vlc8_build` refuses (returns false) when a code would be
  longer, or when the pool would exceed 1,024 entries.
- **One-symbol codes.** One bit long; both bit values decode to the symbol.
- **SH-2 kernel.** Used by `sh2z_vlc8_decode` on SH-2 builds without `SH2Z_FORCE_PORTABLE`
  when the stream address is even (it reads with `MOV.W`); an odd address takes the portable
  path. It follows the GCC SH calling convention (arguments r4-r7, result r0), preserves
  r8-r13, MACH and MACL, and does not touch r14, GBR or PR.
- **Stack.** The builders use about 5 KB of stack; the SH-2 kernel 48 bytes, the C decoder less.

### Code lengths

`sh2z_vlc8_build` is not the optimal length-limited code (package-merge); it is the
contribution's heuristic, frozen exactly so that tables built on the encoder side and on the
SH-2 agree:

1. Huffman, merging the two live nodes smallest by (weight, id), where leaves are numbered
   by symbol and merged nodes after them in creation order.
2. Clamp to `lmax`.
3. While the Kraft sum is over: lengthen the longest code that is shorter than `lmax`
   (ties: smallest frequency, then smallest symbol).
4. While a code can be shortened without going over: shorten the most frequent one
   (ties: smallest symbol).

When Huffman already fits `lmax` the result is Huffman (optimal). Over the host sweep, 106
alphabet and limit pairs needed limiting; 28 of those came out optimal, the mean excess over
package-merge was 1.77% of the coded size, and the worst 33.7% (a long-tailed 256-symbol
alphabet limited to 9 bits). A caller that needs optimal lengths can compute them offline and
build the table with `sh2z_vlc8_build_lengths`.

## How the SH-2 kernel works

- **Marker bit.** The unread bits sit in one register with a marker bit above them
  (`bb = bits | 1 << count`). At least 16 bits are left exactly when `bb >= 0x10000`: the
  refill test is one compare, and no count is kept.
- **No variable shift.** The SH-2 shifts only by 1, 2, 8 or 16. `bb >> len` is the high word
  of `DMULU.L bb, 2^(32 - len)`. The table stores each length as `4 × (len - 1)`, the byte
  offset of that multiplier in a 16-entry table, so one `MOV.B` gives the index.
- **Two byte arrays.** The first level is `s[2^w]` (symbol) and `n[2^w]` (length field): one
  `MOV.B` each. A field with bit 7 set sends the decoder to the pool.
- **Refill.** One 16-bit unit at a time: `bb += H × (unit + 0xFFFF)`, with `H = 2^count` from a
  256-entry table indexed by `bb`'s high or low byte. `MOV.W` and `SWAP.B` read the unit.
  When the pointer reaches the end, nothing is read and a zero unit is appended; the reader
  counts these (saturating at 2), and two mean a bit past the end was consumed.
- The main loop is 15 instructions per first-level symbol; the multiply overlaps the output
  pointer update.

## Evidence

### HOST (`saturn/tests/test_vlc.c`, `ctest -R vlc_exact`)

GCC and Clang Release with `SH2Z_STRICT=ON`, and ASan/UBSan. The independent oracle
[`tests/vlc_oracle.h`](tests/vlc_oracle.h) shares no code with the library: Huffman by sorting
the live nodes at every merge, the length limit by tuple comparisons over all symbols,
canonical codes by sorting (length, symbol), the table by searching for the code that matches
each index, decoding one bit at a time, and the reader state from the number of bits consumed.

- **Builder:** 3,300 (alphabet, `w`, `lmax`) builds over 11 alphabet shapes (uniform, Zipf,
  Fibonacci, equal, powers of two, one symbol, two symbols, one huge weight with ones, random
  32-bit, long tail, geometric), 1 to 256 symbols, every `w` 1..8 and every `lmax` w..16: the
  table, lengths and codes equal the oracle's byte for byte, and the 845 refusals agree. Every
  table also equals the one built by the contributed builder (except that a one-symbol table
  now decodes bit 1 too) and the one `sh2z_vlc8_build_lengths` builds from the reported
  lengths. Lengths satisfy Kraft with equality (one half for a single symbol), are prefix-free
  and at most `lmax`; costs are compared with package-merge as above.
- **`sh2z_vlc8_build_lengths`:** 3,000 complete, incomplete, over-subscribed, too-long,
  single and empty length sets, accepted or refused as the header says.
- **Round trips:** 955 messages, 4,154,640 symbols and 13,128,654 bits (from 0 symbols to
  20,000) through stream buffers of exactly `2 × units` bytes on the heap, so ASan sees any
  read past a stream, with both decoders in one call and in random chunks (12,031 chunked
  decodes): symbols, reader state and return value equal the oracle's.
- **Truncation and fuzz:** 10,121 truncated streams, 2,513 random byte streams (743,460
  symbols) through built tables, 4,000 random tables in the table format that pass the check,
  and 20,000 garbage tables (the check agrees with the oracle's restatement; 247 accepted
  tables decoded in bounds against the oracle's table walker).
- **Negative controls (8, all caught):** Huffman ties to the higher id; lengthening the most
  frequent symbol; spare room to the least frequent symbol; canonical order (length, -symbol);
  most-significant-first bits; overrun flagged one bit early; pad count not saturating; a
  one-symbol table decoding bit 1 as symbol 0.

### MODELLED ([`benchmarks/vlc-model`](benchmarks/vlc-model/README.md))

The compiled big-endian SH-2 objects run in the pinned Yabause interpreter. Before any timing,
2,000 random builds (728 refusals) and 8,000 streams (2,000 of them truncated, plus 501 random
format tables and 2,000 streams at an odd address) check every table, symbol, return value and
reader state of the kernel, the library's C path and a plain C decoder against the oracle
(3,355,101 symbols per entry), and any read of stream bytes past the end stops the run.

Decode cost, cycles per symbol (per coded bit), 16 corpora of 4,096 symbols:

| Alphabet (`w`, `lmax`) | bits/symbol | SH-2 kernel | library C | plain C | kernel vs C |
| --- | --- | --- | --- | --- | --- |
| Zipf, 256 symbols (6, 12) | 6.25 | 40.51 (6.48) | 73.92 (11.82) | 75.31 (12.04) | 1.82× |
| near-uniform, 256 (8, 8) | 8.00 | 31.00 (3.87) | 53.00 (6.62) | 53.49 (6.69) | 1.71× |
| long tail, 30 + 226 (6, 12) | 3.26 | 24.99 (7.67) | 48.21 (14.79) | 50.62 (15.53) | 1.93× |
| 40 draws, weights 2^0..2^13 (5, 10) | 3.61 | 25.61 (7.09) | 50.14 (13.89) | 52.55 (14.56) | 1.96× |
| geometric, 16 symbols (8, 12) | 1.54 | 20.49 (13.35) | 40.38 (26.30) | 43.03 (28.02) | 1.97× |

"Library C" is `sh2z_vlc8_decode_portable` compiled by GCC 13.2 `-O2`; "plain C" is a
straightforward decoder with a bit count and variable shifts (GCC calls the libgcc shift
helpers on SH-2). A call costs about 160 cycles more than its symbols (setup, register saves).

Build cost, cycles per table (mean of 16):

| Alphabet | `sh2z_vlc8_build` | contributed builder | speed-up | `build_lengths` |
| --- | --- | --- | --- | --- |
| Zipf, 256 | 140,645 | 2,818,306 | 20.0× | 68,801 |
| near-uniform, 256 | 111,819 | 3,200,758 | 28.6× | 50,593 |
| long tail, 256 | 150,769 | 2,853,780 | 18.9× | 74,471 |
| 40 draws | 40,622 | 187,935 | 4.6× | 24,272 |
| geometric, 16 | 27,938 | 584,280 | 20.9× | 23,949 |

The builder makes byte-identical tables to the contributed one; it is faster because it sorts
once (radix or insertion sort), merges Huffman nodes from two queues, keeps a cursor per
length when lengthening, and fills the pool in one pass over the symbols.

The numbers above are from the local run with the pinned Yaul GCC 13.2. The committed capture
[`results.json`](benchmarks/vlc-model/results.json) is the one from CI.

## Not included

No rANS, tANS or two-symbols-per-lookup table: the contribution judged them on table size
against the 4 KB cache and did not build them. No SCU DSP kernel. No 32-bit (two-unit) refill;
it would save a refill on long codes at the cost of the one-compare test.
